# Android APK Builder — GitHub Actions

Android-приложение на Kotlin, собираемое через GitHub Actions. Создавать APK, скачивать и устанавливать на телефон можно без компьютера и VPS.

## Автоматическая сборка и тестовая подпись без Secrets

- Изменение кода в `main` автоматически запускает сборку.
- Есть кнопка **Run workflow** для ручного запуска.
- Версии увеличиваются автоматически: `1.0.3`, `1.0.4`, и далее.
- Каждая сборка использует **один постоянный ТЕСТОВЫЙ ключ**: `signing/test-debug.jks`.
- Ничего не нужно настраивать в GitHub Secrets, Termux не нужен.
- Перед загрузкой APK workflow проверяет цифровую подпись и сертификат.
- В Artifacts появится `APK-Starter-v1.0.N`, внутри — `APK-Starter-v1.0.N.apk`.

**⚠️ ВАЖНО: ТОЛЬКО ДЛЯ ТЕСТОВ.** Ключ специально хранится в приватном репозитории и имеет известный пароль. Это **не секрет** и не защита издателя: всякий, у кого есть доступ к ключу, сможет подписывать им программы. Нельзя использовать его для публичных релизов или приложений с реальными пользовательскими данными. Для выпуска серьёзного приложения потребуется отдельный защищённый ключ.

## Как получить APK на Android

1. Откройте [Actions → Build Android APK](https://github.com/Mihail9990/Ttt/actions/workflows/build-apk.yml).
2. При желании выберите **Run workflow**, либо откройте автоматическую сборку после коммита.
3. После **зелёной галочки** откройте выбранный запуск.
4. Прокрутите до раздела **Artifacts** и скачайте ZIP с `APK-Starter-v...`.
5. Распакуйте ZIP, откройте APK в файловом менеджере и установите приложение.

## Как работают обновления

APK с номером версии больше предыдущего, тем же `applicationId` и **той же цифровой подписью** обычно устанавливается поверх предыдущего, сохраняя его данные.

Ранее установленные APK версии `1.0.1` или `1.0.2` были подписаны **другими временными ключами**. Перед установкой новой версии с постоянной тестовой подписью **нужно один раз удалить** старую APK Starter (локальные данные старой установки будут удалены). После этого новые тестовые сборки можно устанавливать поверх предыдущих.

**Не заменяйте и не удаляйте** `signing/test-debug.jks`: это изменит сертификат и может сломать обновление. При подготовке коммерческих приложений потребуется отдельная безопасная схема подписи.

## Файлы проекта

- `app/src/main/java/com/example/apkstarter/MainActivity.kt` — экран приложения.
- `app/src/main/res/values/strings.xml` — название.
- `app/src/main/res/drawable/ic_launcher.xml` — иконка.
- `app/build.gradle.kts` — настройки Android, номера версий и тестовая подпись.
- `signing/test-debug.jks` — постоянный **не защищённый** тестовый сертификат.
- `.github/workflows/build-apk.yml` — сборка на GitHub и публикация APK.
- `docs/SIGNING_ON_ANDROID.md` — пояснение о безопасной подписи для будущих релизов.
