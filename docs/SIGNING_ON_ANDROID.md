# Постоянная подпись APK — настройка с Android

Сначала создайте собственный ключ **локально на телефоне**. Никогда не пересылайте его или пароль в ChatGPT, Telegram или публичный GitHub.

## 1. Установите Termux

Официальная страница: https://f-droid.org/packages/com.termux/  
Откройте Termux, выполните:

```sh
pkg update && pkg install openjdk-17 coreutils -y
```

## 2. Создайте постоянный ключ

```sh
keytool -genkeypair -v \
  -keystore ~/apkbuilder-release.jks \
  -storetype PKCS12 \
  -alias apkbuilder \
  -keyalg RSA -keysize 3072 \
  -validity 10000 \
  -dname "CN=APK Builder, OU=Android, O=Personal, C=KZ"
```

Придумайте длинный пароль и **сохраните его** в менеджере паролей. Он понадобится для установки обновлений через GitHub Actions. Формат PKCS12 использует один пароль для контейнера и ключа. Ключ с alias `apkbuilder` создаётся один раз и используется для всех последующих сборок **данного приложения**.

## 3. Создайте значение первого секрета

Дайте Termux доступ к общему хранилищу:

```sh
termux-setup-storage
```

Разрешите доступ. Затем выполните:

```sh
base64 -w 0 ~/apkbuilder-release.jks > ~/storage/downloads/apk_keystore_base64.txt
```

В папке Android **Downloads** появится текстовый файл `apk_keystore_base64.txt`. Внутри — одна длинная строка. Скопируйте её целиком (не вставляйте в чат).

## 4. Добавьте два GitHub Secrets

Откройте на телефоне:

https://github.com/Mihail9990/Ttt/settings/secrets/actions

Выберите **New repository secret** и создайте:

| Name | Secret |
|---|---|
| `APP_KEYSTORE_BASE64` | Вся строка из `apk_keystore_base64.txt` |
| `APP_KEYSTORE_PASSWORD` | Пароль, который вы указали при создании ключа |

После сохранения двух секретов **удалите временный текстовый файл** из Downloads:

```sh
rm ~/storage/downloads/apk_keystore_base64.txt
```

**Не удаляйте** оригинальный файл `~/apkbuilder-release.jks`. Сделайте его защищённую резервную копию в надёжном месте и храните пароль отдельно. GitHub Secrets не позволяют прочитать сохранённые значения позднее.

## 5. Запустите новую сборку

https://github.com/Mihail9990/Ttt/actions/workflows/build-apk.yml

Выберите **Run workflow**. Должны появиться два артефакта:
- `Android-Debug-v...` — тестовый APK, подписанный вашим постоянным ключом;
- `Android-Release-v...` — готовый к распространению APK с тем же сертификатом.

Устанавливайте **Release**. Следующие Release APK с увеличенным номером версии и тем же `applicationId` обновляют приложение поверх установленного.

**Внимание:** первый APK до настройки этих секретов подписывался временным debug-ключом. Его нужно **один раз удалить**, перед установкой первого постоянно подписанного APK. Это удалит локальные данные старой тестовой программы. После этого обновления должны устанавливаться поверх приложения без удаления данных.

Если установленное приложение не обновляется, проверьте: совпадает ли `applicationId`, используется ли прежний ключ подписи и вырос ли `versionCode`.

Примечание: каждый отдельный коммерческий проект желательно подписывать собственным ключом, а не делить одну пару ключей между не связанными приложениями.
